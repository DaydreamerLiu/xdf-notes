文件管理

计算机 · 理论笔记 · 6 节

来源: 计算机-操作系统-第 1 课(文件的基本概念, 回放录音转写)

板块总览

文件管理是操作系统考试的重要板块。操作系统对"看得见的资源"负责两件事: 进程管理管 CPU、内存管理管内存, 而文件管理管外存上的数据——把磁盘上散乱的存储组织成"文件"这种对用户友好的形式, 并管好文件的访问与保护。

本课是文件管理的开篇: 一个文件"存在"意味着什么(FCB/目录项) → 文件有哪些基本操作 → 打开文件表如何让操作变快 → 如何保护文件不被乱改。后续课程还会讲文件在磁盘上的物理结构、目录结构、文件系统实现, 本课是全章的"存在论"地基。

一、文件与文件控制块(FCB)

定义 每个文件都有一个文件控制块(FCB), 记录它的名字、类型、权限等一切属性。FCB 存放在目录文件中, 所以也叫目录项。目录文件本身也是一个文件, 它的内容就是一个个目录项排成的序列。

直觉 操作系统"看"目录, 不是看人类理解的文件夹图标, 而是看一个目录文件——里面的每一项就是一个 FCB。这和进程管理完全同构: 一个程序哪怕代码还在磁盘上, 只要没有 PCB, 对操作系统来说进程就不存在;一个文件只要没有 FCB, 对操作系统来说它就不存在。存在性由控制块定义, 这是操作系统的统一思维。

按名找文件的过程(目录存在的意义):

  1. 打开文件 a 所在的目录文件, 加载进内存;
  2. 按文件名逐个遍历目录项, 直到找到同名的那个(即 a 的 FCB);
  3. 从 FCB 中取出 a 在外存的物理地址(如首磁盘块地址 + 占几个块);
  4. 定位并访问文件数据。

二、文件的基本操作

操作 做两件事: 数据区 + 目录区
创建 ① 在外存分配空间存数据; ② 在所在目录文件中新增一个目录项(FCB)
删除 ① 回收占用的外存空间; ② 删除目录文件中对应的目录项
读 系统调用给出文件名 + 读入内存的目标地址; 按名找目录项 → 得外存地址和块数 → 逐块读进内存指定地址
写 与读对称: 给出文件名 + 内存源地址; 按名找目录项 → 从内存逐块写回外存
截断 只把文件的长度属性置零, 逻辑上清空内容, 文件名和属性保留
设置读写位置 每个文件有一个读写指针(默认指向第一个磁盘块), 可设置到指定位置, 下次读写从这里继续

直觉 创建/删除必须是"数据区 + 目录区"两半: 只分配空间不建目录项, 文件是"不存在"的; 只删目录项不回收空间, 那块磁盘空间就永远找不回来了。任何基本操作, 都同时在和数据区与目录区打交道——这是本课的易错点。

截断文件的巧思: 内容全过时需要重写, 删除再重建要走"回收空间 + 删目录项 + 分配空间 + 建目录项"四条链路; 而截断只是把长度清零, 剩下全保留, 一步到位。易错 截断 ≠ 删除——删除连文件"身份"(FCB)一起消失, 截断只清空内容。

读指针的现实例子: 文本编辑器关闭文档时记住读到哪, 下次打开自动回到上次位置——就是"设置读写位置"的应用。

三、打开文件与关闭文件 必考

为什么需要打开: 如果每次读写都走"检索目录 → 加载目录文件 → 遍历目录项 → 找物理地址", 代价太大。打开 = 把"找目录项"这件事提前做一次, 把结果缓存到内存, 之后所有操作直接复用。

打开的过程: 把该文件的属性(目录项内容)从外存复制到内存的打开文件表, 并返回给进程一个表项索引号(编号)。此后进程对这个文件的一切操作都只凭索引, 不再需要文件名——Windows 管这个编号叫文件句柄, Linux 管它叫文件描述符。

两级打开文件表:

  • 系统打开文件表(全系统只有一张): 存文件的属性(文件名、类型、长度等)——这些与"谁在用"无关, 一份就够。只要有任一进程打开了某文件, 系统表里就有它。
  • 进程打开文件表(每个进程一张): 存进程视角下的信息——引用的系统表项索引、该进程对文件的访问权限、该进程的读写指针位置等, 与进程强相关。

直觉 为什么要分两级? 属性是"公共的"——a、b 同时打开同一个文件, 文件还是那一个, 属性存一份即可; 但读写指针是"私有的"——a 读到文件中间, 不该影响 b 从开头读。公共的进系统表, 私有的进进程表, 各管各的。

两个常考点:

  1. 打开后一切走索引, 文件名退出舞台: 打开文件表里只认索引号; 文件名只在"打开"这个检索动作里用一次。
  2. 引用计数器: 系统表项里有一个计数器, 记录当前有多少进程打开了该文件(a、b 都打开 → 计数为 2)。某个进程关闭文件, 只删除它自己的进程表项, 系统表项计数减一;计数不为 0 绝不删除系统表项——因为还有别人在用; 只有减到 0, 才真正删除系统表项。这是打开/关闭最常见的出题点: 关闭文件 ≠ 从系统表里删属性。

四、文件保护 高频

为什么需要: 文件常被多个用户共享, 共享带来"被破坏"或"被未核准用户修改"的风险, 所以必须控制每个用户对文件能做什么。

访问类型: 读、写、执行、添加、删除、列清单等——重点记前三个: 读、写、执行。

三种保护方法:

  1. 访问控制(表记录法, 最重要): 用一张表记录"哪些用户对该文件有什么权限", 权限信息存在 FCB 中。用户分三类:
  2. 主用户(创建该文件的用户)
  3. 组(需要共享文件、访问需求类似的一类用户)

  4. 其他用户(系统内其余用户) 三种用户各自对"读/写/执行"打勾。Windows 里"文件属性 → 安全"页签就是它——你会看到用户组可读可写不可执行之类的勾选项。实现形态可以是用户权限表、访问控制表(ACL)、访问控制矩阵, 本质都是同一张表, 换皮不换核。

  5. 口令保护: 创建文件时设一个口令, 系统把它附在 FCB 上, 访问时必须对暗号(提供口令)才能放行。

  6. 加密保护: 对文件内容加密, 访问时提供密钥才能解开。加密的具体机制本课不用深究。

直觉 三种方法其实对应三种信任模型: 访问控制 = "按身份发权限"(表), 口令 = "按暗号验身份", 加密 = "不验身份, 只有钥匙才打得开"。考试默认考第一种。

五、知识连接

  • 与进程管理同构: PCB ↔ FCB, 进程表 ↔ 打开文件表。"有没有控制块"决定"存不存在", 是操作系统反复出现的思维模式。
  • 与文件共享呼应: 保护是为共享服务的; 后面讲共享(硬链接/软链接)时会看到"多个目录项指向同一文件", 与本节引用计数器的思想一脉相承——多个引用共用一个实体, 计数归零才释放。
  • 为本板块后续铺路: 本课解决"逻辑上怎么找到文件"(FCB + 目录); 接下来会问"文件数据在磁盘上怎么排"(连续/链接/索引分配)、"目录怎么组织"(单级/多级/树形)、"文件系统怎么实现"——FCB 和目录是本课的锚点, 后面全是在这两个概念上盖楼。
